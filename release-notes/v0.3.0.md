# SquirrelBIOS v0.3.0

The hand-off era is done. On QEMU's three machines the firmware loads a
real OS image, jumps to it, and proves the contract in CI. RISC-V boots
Linux on a large node; x86 boots Squirrel-OS/2 through `INT 13h`;
AArch64 keeps the Linux `Image` path from v0.2.0.

After this tag the roadmap turns toward a comprehensive x86 PC BIOS for
**v1.0.0**. See [ROADMAP.md](../ROADMAP.md).

Includes #45–#66 on top of v0.2.0: milestone 6 (large RISC-V node) and
milestone 7 (Squirrel-OS/2 on x86), plus the RAS shutdown path.

## x86

### Added
- A disk whose LBA 192 ends in `S2OK` is loaded to `0x8000` and entered
  there (Squirrel-OS/2 layout). (#64)
- `INT 13h` `AH=0x00` / `0x02` / `0x08` / `0x42` read the primary master
  so a conventional boot sector can load a kernel itself; `INT 10h`
  `AH=0x0E` is a VGA teletype. (#65)
- `INT 15h` `E820` returns the SQMM memory map. (#64)
- `tests/os-boot.sh` boots a real Squirrel-OS/2 `os.img` to a shell
  prompt (not part of `make test`). (#64)

### Fixed
- The x86 stand-in's memory-map check requires a usable entry at 1 MB
  when one is present. (#62)

### Known limitations
- Still a thin runtime: no A20, no keyboard/`INT 16h`, no timer/`INT 1Ah`,
  no ACPI, no option ROM scan, no disk writes. Those are the v1.0.0 path.

## AArch64

Unchanged in behaviour from v0.2.0 for this release. The Linux `Image`
and initrd path stays the platform firmware for `virt`.

## RISC-V

### Added
- `MAX_HARTS` covers QEMU `virt`'s 512-hart limit; `make linux-big`
  brings up 64 harts with a 6.14 test kernel. (#45–#47)
- `fw_dynamic_info.boot_hart` is honoured when it is not hart 0. (#49)
- NUMA: per-socket CLINTs, `numa-node-id` preserved through device-tree
  edits; `make linux-big` defaults to two nodes. (#51)
- AIA `aia=aplic`: sources delegated to S-mode, M-level controllers
  hidden from the tree. (#55)
- PCIe check: `virtio-net-pci` and `nvme` enumerate under
  `/sys/bus/pci/devices` on the big node. (#58)
- Network boot decided: the OS does it; the firmware starts the image
  that is already there. (#56)
- Fatal M-mode faults print a `ras:` line, park other started harts, and
  shut the machine down as an SRST system failure (QEMU exit status 1).
  (#57, #63, #66)

### Fixed
- IPI and RFENCE wait for a hart that is still checking in. (#59)
- Stopped-hart edge cases around HSM and fences. (#48)

### Known limitations
- `aia=aplic-imsic` still does not reach a Linux shell on QEMU 8.2 (same
  with QEMU's OpenSBI). Left for a newer QEMU / `smsiaddrcfg`.
- No SBI debug console (`DBCN`); use UART earlycon.

## Developer experience

### Added
- `make linux-big`, `tests/linux-stress.sh`, and the stress harness for
  many-hart boots. (#45, #50, #61)
- Many new `make test` cases (NUMA, AIA, boot hart, RAS, OS load,
  `INT 13h`, …). The suite is 45 cases at this tag.

## Documentation
- Hand-off contract covers OS image load, `INT 13h`/`10h`/`15h` E820,
  large-node NUMA/AIA notes, RAS lines, and network-boot policy.
- [ROADMAP.md](../ROADMAP.md) / [TODO.md](../TODO.md): hand-off
  milestones 1–7 closed; v1.0.0 is a comprehensive x86 PC BIOS.

## Hand-off contract changes
- x86: `S2OK` fast path, IVT services for disk/teletype/E820.
- RISC-V: many harts, boot hart, NUMA CLINTs, AIA aplic delegation,
  `ras:` + system-failure shutdown.

See `common/handoff.md` for the details.
