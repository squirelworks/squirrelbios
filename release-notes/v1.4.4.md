# SquirrelBIOS v1.4.4

Roadmap B6 to B10, which finishes Phase B (#83). The x86 BIOS now has USB
(four host controller types, keyboard, mouse and disk boot), virtio disks,
network boot over TFTP and VBE 3.0 graphics modes. The roadmap numbered
these v1.4.0 to v1.4.4. They ship together under this tag.

Tag target: `3388eba` (the merge of #116). Includes #101 to #116 on top of
v1.3.1. This is still original code, and `make test` still covers all of
it.

## USB host controllers (B6, #101, #102, #104, #105)

- POST finds UHCI, OHCI, EHCI and xHCI controllers on PCI, resets them,
  enumerates every device, and walks hubs (also hubs behind hubs). It lists
  each device with its address, place, IDs and class, on the screen and
  on COM1 (#111).
- On ICH9, EHCI keeps the high-speed devices and hands the full-speed ones
  to its UHCI companions.
- xHCI gives a device's slot back once it is listed, so a controller with
  few slots can still list many devices.

## USB keyboard and mouse (B7, #106 to #110, #112, #113)

- A USB keyboard on UHCI, OHCI, an EHCI companion or xHCI keeps working
  after POST, with or without hubs in between. Its keys reach `INT 16h`
  and the BDA keyboard buffer like PS/2 keys.
- A USB mouse is served through `INT 15h` `C2xx` (reset, type, init,
  status, handler). The handler gets the mouse's motion and buttons as
  PS/2 packets. A report of 128 up is passed as 127 (#113).
- The USB controller that runs after POST keeps its state in the EBDA.

## USB disk boot (B8, #114)

- When no IDE, SATA or NVMe disk answers, POST looks for a bulk-only USB
  disk on xHCI. It prints `disk: USB disk (bulk-only)`, and that disk is
  `DL = 80h`. It boots like the other disks, and every `INT 13h` disk
  call serves it.
- The disk can sit behind a hub, beside a USB keyboard and mouse on the
  same controller. All three keep working after the boot.
- `AH=48h` names it as `PCI` / `USB` with the device's address.

## virtio disk and network boot (B9, #115)

- When no IDE, SATA, NVMe or USB disk answers, POST looks for a
  virtio-blk device (legacy interface, `1AF4:1001`). It prints `disk:
  virtio disk`, and the device is `DL = 80h`, served like the others.
  `AH=48h` names it as `PCI` / `SCSI`.
- When no disk or CD boots, the BIOS tries the network over a virtio-net
  device (`1AF4:1000`). It gets an address by DHCP, prints the address,
  server and file name, loads the boot file by TFTP to `0x7C00`, and
  enters it with `DL = FFh`. It answers ARP while it loads.
- New build options `CONFIG_VIRTIO` and `CONFIG_NETBOOT`. Both are on by
  default when `CONFIG_PCI` is on.

## VBE graphics (B10, #116)

- `INT 10h` `AH=4Fh` is VBE 3.0 on QEMU's standard VGA (`-vga std`):
  `4F00` controller information, `4F01` mode information, `4F02` set
  mode, `4F03` current mode, `4F06` scan-line length and `4F07` display
  start.
- Modes `111h`/`112h` (640x480), `114h`/`115h` (800x600), `117h`/`118h`
  (1024x768) and `11Ah`/`11Bh` (1280x1024), at 16 and 32 bits per pixel,
  with a linear frame buffer. `4F02` with `BX=3` goes back to 80x25 text.
- New build option `CONFIG_VBE`, on by default when `CONFIG_PCI` is on.

## Memory layout (#106, #109)

- The extended BIOS data area is now 56 KB at `0x92000`–`0x9FFFF` (20 KB
  in v1.3.1). It holds the AHCI structures, the NVMe or virtio queues,
  and the USB controller that runs after POST. The memory map reserves
  it.
- BDA `0x040E` points at it, and BDA `0x0413` is now **584 KB** (620 KB
  in v1.3.1). SQBL loads and `INT 13h` buffers must end below
  `0x92000`.

## Known gaps

- USB disks boot only on xHCI and only with bulk-only transport. There
  is no UAS, and no USB disk boot on UHCI, OHCI or EHCI. There is no
  recovery from a stalled transfer.
- virtio uses the legacy interface only, so a modern-only device
  (`1AF4:1042`) is not found. One request runs at a time.
- Network boot has no routing, so the TFTP server must be on the local
  network. The boot file can be at most 230400 bytes (it must end below
  `0x40000`).
- VBE has a linear frame buffer only: no banked windows, no palette
  functions (`4F08`/`4F09`) and no protected-mode interface. It drives
  QEMU's standard VGA only. Without it, every `4Fxx` call returns
  `AX = 0100h`.
- One boot disk: the first of IDE, SATA, NVMe, USB and virtio that
  answers.
