# SquirrelBIOS v0.2.0

Real operating systems now boot. RISC-V has an SBI that takes Linux to a
busybox shell on several harts, AArch64 boots a stock Ubuntu arm64 kernel
with an initrd, and x86 can load more than one sector and shows a working
VGA text screen. `make test` grew from 6 cases to 37 and runs in CI.

Includes #7 (roadmap and task list), #8–#13 (milestone 1: contract tests
and CI), #14–#32 (milestone 2: RISC-V SBI and Linux), #33, #34, #42, #43
(milestone 3: x86), #35–#38, #40 (milestone 4: AArch64), #39 and #41
(fixes found along the way).

## x86

### Added
- The boot sector must end in `0xAA55`. Without it the firmware prints
  `disk: boot sector has no 0xAA55 signature` and halts instead of jumping
  into garbage. (#33)
- Multi-sector boot images: a boot sector with an `SQBL` header at offset
  `0x1F0` asks for 1–128 more sectors and a load address. The firmware
  reads them (with the same retries as the boot sector) before the jump,
  and refuses loads that overlap its own data or run past 640 KB. (#34)
- The VGA is programmed for 80x25 colour text with an original 8x16 font,
  so the QEMU window now shows the firmware's messages, not just COM1. (#43)

### Fixed
- Each CMOS read now disables NMI while it selects the register, then
  restores the default index, as the CMOS/RTC hardware expects. (#42)
- The firmware stack moved to `0x0600` so an image loaded low can't
  overwrite it. (#34)

### Known limitations
- Images still load below 1 MB in real mode: no A20, no `bzImage`, no ACPI.
  These are on the speculative list in `TODO.md`.
- Only the primary master ATA disk is tried.

## AArch64

### Added
- The Linux arm64 `Image` header is honoured: `text_offset`, the
  placement flag and `image_size`. The firmware prints where it loaded the
  kernel. A stock Ubuntu 24.04 arm64 kernel boots to a busybox initramfs.
  (#38)
- QEMU's `-initrd` is loaded after the kernel (4 KB aligned) and recorded
  as `linux,initrd-start` / `linux,initrd-end` in `/chosen`. (#40)
- A kernel too big for RAM is refused with `kernel does not fit in RAM`.
  RAM size comes from fw_cfg, or from the device tree `/memory` node when
  QEMU leaves fw_cfg at 0. (#37)
- An fw_cfg DMA that never completes gives up after 1 second with a
  message, instead of hanging. (#36)

### Fixed
- The image is entered with MMU, D-cache and big-endian modes off at the
  current exception level, and the I-cache invalidated, on purpose rather
  than by luck. Works at EL1 and EL2. (#35)

### Known limitations
- No PSCI or GIC set-up in the firmware: QEMU's own PSCI and the device
  tree cover what Linux needs.

## RISC-V

### Added
- An SBI 1.0 implementation: base, TIME (`set_timer` on the CLINT), IPI,
  RFENCE, HSM (`hart_start`, `hart_stop`, `hart_get_status`) and SRST
  (shutdown and reboot through QEMU's test device). (#17–#19, #21–#23, #25)
- `-kernel` images are entered in S-mode when QEMU asks for it
  (`next_mode`), with supervisor faults and interrupts delegated. (#15, #16)
- IPIs and remote fences reach every started hart, so Linux runs on
  several harts without soft lockups. (#31)
- The firmware region is closed to S-mode with PMP and listed as
  `no-map` reserved memory in the device tree. (#26, #27)
- Zicbom, Zicboz and Sstc are enabled for S-mode in `menvcfg`, which Linux
  6.8 needs to get past early boot. (#28)
- M-mode traps print `trap mcause=...` and halt instead of hanging
  silently. (#14)
- `make linux-shell`: boots a pinned Ubuntu riscv64 kernel with a busybox
  initramfs to a shell prompt and powers it off. (#29)

### Fixed
- The trap handler's frame stays inside the trap stack. (#20)
- S-mode is entered with `satp` and `sp` cleared, including after a
  `hart_stop` and restart. (#24)
- A stopped hart's Sstc timer is cleared, so it restarts without a stale
  timer interrupt. (#30)
- The UART is programmed for 115200 8N1 instead of relying on QEMU's
  reset values. (#41)

### Known limitations
- No legacy SBI v0.1 calls and no debug console (DBCN), so
  `earlycon=sbi` doesn't work. Use the `uart8250` earlycon.
- Only QEMU `virt` is supported (fixed CLINT, UART and test device
  addresses).

## Developer experience

### Added
- `make test` has 37 cases, up from 6, covering every failure message and
  hand-off rule. (#8–#12, and each feature PR above)
- CI runs `make test` on every push and pull request and keeps the serial
  logs. (#13)
- `tests/smoke.sh` can match a regex (`~`), require a string to be absent
  (`!`) and require QEMU's exit status (`@exit=N`). (#11, #14, #25)
- The RISC-V multi-hart tests wait on time, not loop counts, so they no
  longer fail on a busy machine. (#39)

## Documentation
- `ROADMAP.md` and `TODO.md`: the goals, working rules and a one-PR-per-box
  task list. Milestones 1–4 are done. (#7)
- `riscv/README.md` explains how to try Linux on the firmware. (#32)
- `arm/README.md` and `x86/README.md` describe the new loading rules.

## Hand-off contract changes
- x86: the `0xAA55` check, the `SQBL` extra-sector header and its failure
  messages, and the VGA text mode at hand-off. (#33, #34, #43)
- AArch64: `Image` header placement, the RAM fit check, the initrd
  properties in `/chosen`, and the SCTLR state at entry. (#35–#38, #40)
- RISC-V: the image is entered in S-mode, with the SBI, delegation, PMP,
  reserved memory and `menvcfg` described in full. QEMU's `-kernel` asks
  for S-mode, so images that expected M-mode entry now start in S-mode.
  (#15–#31)

See `common/handoff.md` for the details.
