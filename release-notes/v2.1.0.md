# SquirrelBIOS v2.1.0

The first release with 64-bit firmware. `PLATFORM=x86_64-uefi` is an
original UEFI-class firmware for `qemu-system-x86_64`: it boots
`BOOTX64.EFI` from a FAT disk, boots Linux x86-64 to a shell with ACPI,
starts every CPU, verifies Secure Boot signatures with our own keys, and
still boots legacy disks, floppies and CDs through a CSM. AArch64 and
RISC-V `virt` get the same UEFI-class interface from a shared core. The
x86 PC BIOS gains the remaining v1.4.x follow-ups.

This covers roadmap Phase C1 to C4 (numbered v2.0.0-alpha to v2.1.x),
plus D1 and D3 from Phase D and the first parts of F1 and F2. They ship
together under this tag.

Tag target: the merge of the release-prep PR. Includes #118 to #140 on top
of v1.4.4. It is still all original code (no EDK2, OVMF, SeaBIOS, OpenSBI
or U-Boot), and `make test` covers all of it: **217 cases** (110 at
v1.4.4).

## x86-64 UEFI-class firmware (C1, #118, #119, #122 to #125)

- Reset vector to long mode, page tables, memory map from fw_cfg, COM1
  console. A 1 MB flash image for `qemu-system-x86_64 -bios`, on `q35`
  and `pc`.
- EFI system table, boot services (memory, events and timers, handle and
  protocol database), PE32+ loader with LoadImage/StartImage/Exit.
- Simple Text Input/Output on COM1 (UTF-8, ANSI), Block I/O on virtio-blk
  with GPT/MBR partitions, read-only FAT12/16/32 Simple File System, and
  boot of `\EFI\BOOT\BOOTX64.EFI` from the ESP.
- GOP on QEMU's standard VGA (640x480, 800x600, 1024x768 at 32 bpp),
  runtime services (GetTime, variables, ResetSystem), ExitBootServices.
  Only the runtime code and data pages are kept after exit (#132); a test
  overwrites every boot-services page and then calls the runtime services
  (#136).

## ACPI 6.x and SMBIOS 3.x (C2, #128)

- RSDP 2.0, XSDT, FADT 6.4, FACS, MADT, HPET, MCFG (q35), and a DSDT
  generated at boot by an original AML writer. SMBIOS 3.0 entry point and
  tables.
- fw_cfg kernel command line and initrd for a Linux EFI stub.
- Linux 6.8 x86-64 boots to a shell with ACPI on `q35` and `pc` and powers
  off through `\_S5` (`make linux-uefi`, optional, not in CI).

## CSM: legacy boot from the 64-bit firmware (C3, #126, #129, #133)

- When nothing boots the UEFI way, the firmware shadows the x86 PC BIOS
  at `F0000`, drops to real mode and runs the legacy POST. Floppies, MBR
  disks on IDE, AHCI, NVMe or USB, and CDs boot from `squirrel-bios.fd`.
- Squirrel OS/2 2.0.2 `os.img`, `floppy.img` and `cd.iso` boot to their
  shell this way.
- The CSM refuses to run while Secure Boot is on.

## SMP and Secure Boot (C4, #127, #130)

- INIT-SIPI-SIPI bring-up of every CPU, `EFI_MP_SERVICES_PROTOCOL`,
  xAPIC and x2APIC (x2APIC when there are more than 255 CPUs, or with
  `CONFIG=x2apic`), an MPS 1.4 table. Tested with up to 64 CPUs.
- Verify-only Secure Boot with your own keys: SHA-256, RSA-2048
  PKCS#1 v1.5, X.509 and Authenticode, all original. db and dbx come from
  fw_cfg (`opt/org.squirrelworks/db`, `.../dbx`). An image whose hash is
  not in db and whose signature no db key verifies is refused, and a dbx
  hash or key always refuses. An unreadable db or dbx fails closed.

## Large nodes: NUMA and RAS (first parts of F1 and F2, #132, #136, #140)

- MADT built from the started CPUs, with x2APIC entries past APIC ID 254.
  The ACPI area has room for 1024 CPUs.
- SRAT, SLIT and HMAT from QEMU `-numa` (including `hmat=on` and
  memory-only nodes). Linux sees the nodes, distances and HMAT.
- QEMU `pxb`/`pxb-pcie` expanders become extra PCI root bridges in the
  DSDT, each with its NUMA node (`_PXM`) (#140).
- Machine checks: MCA banks enabled on every CPU, errors left from before
  a reset reported in the BERT, HEST lists the MCE and CMC sources. Linux
  prints them as "Error records from previous boot".

## AArch64 and RISC-V UEFI-class firmware (D1, D3, #131, #135)

- New `PLATFORM=aarch64-uefi` (`arm/uefi/squirrel-bios.fd`) and
  `PLATFORM=riscv64-uefi` (`riscv/uefi/squirrel-bios.bin`), built from a
  shared UEFI core in `common/efi/`.
- AArch64: MMU, PL011, generic timer, PL031 RTC, PSCI, GICv2/v3, the
  device tree as a configuration table, and SBBR-like ACPI tables (FACP,
  APIC, GTDT, SPCR, DBG2, MCFG, IORT, DSDT). Ubuntu 24.04 arm64 boots to a
  shell with the device tree or with ACPI, up to 4 CPUs.
- RISC-V: the SBI (now SBI 2.0 with DBCN and SSE, UART and CLINT/ACLINT
  found in the device tree) plus the UEFI core in S-mode,
  `RISCV_EFI_BOOT_PROTOCOL`. Linux riscv64 6.8 boots to a shell with 4
  harts.
- Both boot `\EFI\BOOT\BOOTAA64.EFI` / `BOOTRISCV64.EFI` from virtio-blk
  on virtio-mmio, from NVMe or virtio-blk on PCI (#137, the first step of
  D4's shared drivers), or QEMU's `-kernel`/`-initrd`/`-append`. Several
  disks can be present at once.
- Security fix in the RISC-V SBI: DBCN and SSE buffers inside the
  firmware's own 2 MB are refused.

## x86 PC BIOS follow-ups (#129, #133, #134, #138)

- USB disk boot on UHCI, OHCI and EHCI (only xHCI before), and USB
  Attached SCSI (UAS) on EHCI and, with streams, on xHCI at super speed.
- USB stall recovery (bulk-only reset recovery and one retry) on every
  host controller. An EHCI bug that left the async schedule on and cost
  20 ms per transfer is fixed.
- virtio-blk modern interface (`1AF4:1042`).
- VBE banked windows at `A000h`, 8-bit palette modes, `4F05h`, `4F08h`,
  `4F09h`.
- El Torito diskette emulation for CDs.
- Network boot through a router (the DHCP subnet mask and router are now
  used).
- The NVMe completion wait no longer times out on a slow machine (#135).

## Known gaps

- QEMU only. Real boards are research (`boards/`, roadmap C5 and D2).
- x2APIC with more than 255 CPUs and more than one ECAM segment are
  built but not testable under QEMU x86 TCG.
- FAT is read-only. Block I/O on x86-64 is virtio-blk; AHCI and NVMe disks
  boot through the CSM, not natively.
- Variables live in RAM and are lost at power-off; a variable is at most
  256 bytes, so a large db or dbx is not exposed as a variable.
- No EINJ, no VBE protected-mode interface, no El Torito hard-disk
  emulation yet.
