# SquirrelBIOS v2.2.0

Everything on `main` since v2.1.1 (`f572f71`). The shared UEFI core grows
native disks, FAT write, USB storage, network boot (including HTTP with
DNS names) and serial-over-LAN; x86-64 adds non-volatile and authenticated
variables, TPM measured boot, SMM with EINJ, IPMI/Redfish stubs and CXL
tables. The legacy x86 BIOS gets El Torito hard-disk emulation and the
VBE protected-mode interface. AArch64 brings its own EL3 PSCI/GIC and a
Raspberry Pi 3 bring-up on QEMU. Phase E lands in full: POWER, SPARC,
m68k, MIPS, LoongArch and s390x. The tree is GPL-3.0.

This covers roadmap C5 (except the real board), D2 (Pi 3 on QEMU), D4,
all of Phase E, and F1–F4 as far as they are testable under QEMU today,
including F2-CXL and F3-DNS (#167).

Tag target: the merge of the release-prep PR. Includes #141 to #167 on
top of `f572f71` (v2.1.0 / v2.1.1). Still all original code (no EDK2,
OVMF, SeaBIOS, OpenSBI, U-Boot, OpenBIOS or SLOF). `make test` covers
it: **334 cases** (217 at v2.1.0).

## Shared UEFI core: disks, FAT write and USB (D4, #142, #145)

- `x86_64-uefi` builds its boot services from `common/efi/`. AHCI, NVMe
  and virtio-blk (PCI) are native Block I/O on x86-64; the same drivers
  serve AArch64 and RISC-V. The DSDT is written through `common/efi/aml.c`.
- FAT12/16/32 Simple File System can write: create and grow files on the
  ESP.
- USB mass storage on xHCI boots `\EFI\BOOT\BOOT*.EFI` on every UEFI
  architecture.
- OS/2 bring-up fixes (#162): virtio-blk waits by the clock (and FAT reads
  contiguous clusters in one go) so a multi-megabyte `BOOTX64.EFI` loads
  reliably; GOP sets the VGA palette address source so the screen is not
  blank; at ExitBootServices (and before the CSM) the PIC, APIC LVTs and
  8042 are left as a BIOS leaves them.

## UEFI network boot, HTTP, DNS and SoL (F3, F4, #143, #146, #167)

- Simple Network Protocol on virtio-net, with a PXE-style DHCP+TFTP boot,
  on x86-64, AArch64 and RISC-V UEFI.
- HTTP boot over a small TCP stack (HTTP/1.1 with Content-Length, chunked
  and close-delimited bodies, redirects). File buffers are capped at 1 GB.
- DNS A-record client (`common/efi/net_dns.c`): DHCP option 6 supplies the
  resolver, so HTTP boot accepts `http://name/...` URLs. A miss prints
  `net: cannot resolve …` and falls through (#167).
- Serial-over-LAN style console mirror over UDP (output per line, input
  from the same host) until ExitBootServices; for trusted networks only.
- Four x86-64 UEFI nodes can diskless-netboot the same image at once from
  one TFTP server behind a router (F4).

## Non-volatile variables, Secure Boot keys and TPM (C5, #144, #147)

- Non-volatile UEFI variables in a pflash store (QEMU pflash unit 1, CFI),
  kept across boots and written after ExitBootServices.
- Authenticated writes to PK, KEK, db and dbx; setup and user mode; keys
  enrolled at run time.
- Measured boot with a TPM 2.0 on TIS: PCR extends, the TCG2 protocol and
  event log, and the TPM2 ACPI table. CI installs `swtpm` so the TPM cases
  run.
- Research note for a real board: `boards/ga-g41m-es2l/` (flashing guide
  and `CONFIG=coreboot` land after v2.2.0).

## SMM, EINJ and CXL (F2, #148, #149, #167)

- SMM in q35's TSEG: SMBASE relocation on every CPU, locked before the
  first non-firmware image runs.
- EINJ: a correctable memory error written as CPER into a polled GHES.
- CXL memory enumeration on `x86_64-uefi` with `-M q35,cxl=on`: the
  firmware finds the CXL host bridge (PCI `1b36:000b`), publishes a CEDT
  (CHBS + CFMWS from QEMU's `etc/acpi/tables`) and `ACPI0016`/`ACPI0017`
  in the DSDT (#167).

## IPMI and Redfish stubs (F3, #154)

- BMC on IPMI KCS (QEMU `ipmi-bmc-sim`), SPMI table, SMBIOS type 38, and a
  Redfish host interface stub (SMBIOS type 42).

## Legacy x86: El Torito HD and VBE PMI (#141)

- El Torito hard-disk emulation for boot CDs (diskette emulation was
  already in v2.1.0).
- VBE protected-mode interface (`4F0Ah`).

## AArch64: EL3 PSCI/GIC and Raspberry Pi 3 (D2, #157)

- Own PSCI and GIC secure side at EL3 when QEMU runs with `secure=on`.
- SDHCI driver for SD cards; `configs/aarch64-uefi/rpi3.cfg` and
  `rpi4.cfg`. On QEMU `raspi3b`, `rpi3-uefi-sd` boots from the SD card to
  the EFI stand-in and ExitBootServices. Pi 4 on `raspi4b` and a desk
  board remain open.

## Phase E: POWER, SPARC and stretch targets (#150–#161)

- **E1** `PLATFORM=ppc64le-powernv`: OPAL-style interface; stock Linux
  boots on QEMU `powernv8` (1–4 cores).
- **E2** `PLATFORM=sparc64-sun4u`: IEEE 1275-style client interface (no
  Forth); PCI BARs for IDE, hme and VGA; console interrupt for the OS;
  Linux 6.8 boots and runs `/init` from an initramfs; IDE disk boot (ELF
  on the master, initrd on the slave).
- **E3** stretch firmware that reaches a prompt and hands off: `m68k-virt`,
  `mips-malta`, `loongarch64-virt`, and `s390x` (SCLP console, virtio-blk-ccw
  IPL of an ELF, Linux boot image with initrd and command line).
- One shared device-tree reader in `common/fw/` for the UEFI core and the
  Phase E ports.

## Licence and tooling (#152, #156, #163)

- Licence is GPL-3.0, the same as SquirrelSoft (#163).
- Draft release workflow attaches the three UEFI-class images as well as
  the three legacy ones, and refreshes an existing draft instead of
  failing (#152, #156).

## Known gaps

- QEMU only. Real boards are research (`boards/`: C5 flashing guide for
  the GA-G41M-ES2L; D2 Raspberry Pi 4 on QEMU `raspi4b` and on the desk).
- x2APIC with more than 255 CPUs and more than one ECAM segment are built
  but not testable under QEMU x86 TCG (F1-scale host-side checks still
  open).
- RISC-V AIA MSI mode (`aplic-imsic`) storms on QEMU 8.2; needs QEMU ≥ 9.1
  and a 6.14+ kernel.
- F4 multi-node boot is proven for four nodes in CI; a larger cluster
  (`make f4-scale`: eight nodes, one `-smp 256 -numa`) is optional.
- On AArch64 and RISC-V UEFI, variables still live in RAM (256 bytes each);
  only x86-64 has the pflash store.
- Phase E firmware (powernv, sun4u, m68k, mips, loongarch64, s390x) is
  not in the release asset table yet.
